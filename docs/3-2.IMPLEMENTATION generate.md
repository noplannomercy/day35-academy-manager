Create specs/IMPLEMENTATION.md:

Phase-by-phase implementation plan with checkboxes.

Each Phase include:
1. Goal
2. Estimated time
3. Files to create (checklist format)
4. Implementation strategy
5. Testing checkpoint (checklist) - curl 테스트 또는 화면 테스트
6. Acceptance criteria (checklist)

Phase structure (Backend First 전략):

### Phase A: Backend (API 먼저, 각 Phase마다 curl 테스트)
- Phase 1: Storage & Types & Utils (lib/storage.ts, types/index.ts, lib/constants.ts, lib/utils.ts, data/db.json 초기 데이터)
- Phase 2: Settings API (2개) + 샘플 마스터데이터 → curl 테스트 2개
- Phase 3: Student API (5개) → curl 테스트 5개
- Phase 4: Instructor API (4개) + InstructorSalary API (4개) → curl 테스트 8개
- Phase 5: Class API (5개) + Enrollment API (4개) → curl 테스트 9개 (시간표 충돌 테스트 포함)
- Phase 6: Attendance API (4개) + MakeupClass API (3개) → curl 테스트 7개 (휴일 차단 테스트 포함)
- Phase 7: Payment API (6개) + Refund API (2개) → curl 테스트 8개 (일할계산, 반액납부, 환불 테스트 포함)
- Phase 8: Consultation API (3개) + Holiday API (4개) → curl 테스트 7개
- Phase 9: Waitlist API (4개) → curl 테스트 4개 (정원초과→대기자 전환 테스트 포함)
- Phase 10: Dashboard (1개) + Schedule (2개) + Search (1개) + Export (3개) + Backup (2개) → curl 테스트 9개
- Phase 11: Backend 통합 테스트 (전체 59개 API 연동 시나리오 테스트)

### Phase B: Frontend (확정된 API 호출, 각 Phase마다 화면 테스트)
- Phase 12: Dependencies & Layout & Navigation (AppLayout, Sidebar, Header, GlobalSearch, routing)
- Phase 13: Common Components (DataTable, Pagination, ConfirmDialog, StatusBadge, SearchInput, DatePicker, FormField, EmptyState, LoadingSpinner)
- Phase 14: Settings Page (AcademyInfoForm, LevelManager, SubjectManager, RoomManager, SourceManager, BackupSection)
- Phase 15: Instructor Pages (InstructorList, InstructorForm, SalaryList, SalaryForm)
- Phase 16: Student Pages (StudentList, StudentForm, StudentDetail + 탭: 수강/출석/수납/상담/대기)
- Phase 17: Class Pages (ClassList, ClassForm, ClassDetail, ScheduleEditor, ClassEnrollments, ClassWaitlist)
- Phase 18: Attendance Page (AttendanceBoard, BulkAttendanceForm, AttendanceStats, MakeupList, MakeupForm, HolidayBanner)
- Phase 19: Payment Pages (PaymentList, PaymentForm, PayDialog, ProratedCalculator, UnpaidSummary, RefundForm)
- Phase 20: Salary & Consultation & Holiday Pages
- Phase 21: Dashboard Page (StatCards, EnrollmentChart, TodaySchedule, UnpaidList, TodayReminders, RecentConsultations)
- Phase 22: Schedule Page (WeeklySchedule, MonthlyCalendar) + Export Features
- Phase 23: 통합 테스트 & Polish

CRITICAL CONSTRAINTS:
- Backend First: Phase A (1-11) 완료 후 Phase B (12-23) 시작
- 저장소: data/db.json (lib/storage.ts로 접근)
- Phase A의 각 Phase 완료 후: npm run build + curl 테스트 (해당 Phase API 전부)
- Phase B의 각 Phase 완료 후: npm run build + 화면 동작 확인
- Phase 11에서 전체 API 연동 시나리오 테스트 필수
- 비즈니스 규칙 테스트 필수: 시간표 충돌, 정원 초과, 휴일 차단, inactive 수납 차단, 삭제 제약

⭐ Phase A curl 테스트 포맷 (각 Phase마다 포함):
```bash
# 예시: 수강생 등록
curl -X POST http://localhost:3000/api/students \
  -H "Content-Type: application/json" \
  -d '{"name":"김철수","phone":"010-1234-5678","levelId":"level-1","sourceId":"source-1"}'

# 예상 응답:
# {"data":{"id":"...","name":"김철수","status":"active",...},"message":"수강생이 등록되었습니다."}
```

⭐ Phase A 비즈니스 규칙 테스트 포맷 (해당 Phase에 포함):
```bash
# 예시: 시간표 충돌 테스트 (같은 강사, 같은 시간)
curl -X POST http://localhost:3000/api/classes \
  -H "Content-Type: application/json" \
  -d '{"name":"충돌반","instructorId":"inst-1","schedule":[{"dayOfWeek":1,"startTime":"14:00","endTime":"15:00"}],...}'

# 예상 응답 (에러):
# {"error":"시간표 충돌이 발생했습니다.","code":"INSTRUCTOR_SCHEDULE_CONFLICT","conflicts":[...]}
```

⭐ Phase 11 통합 시나리오 테스트:
- 시나리오 1: 수강생 등록 → 반 수강등록 → 출석 체크 → 수납 등록 → 납부 처리
- 시나리오 2: 정원 초과 → 대기자 등록 → 수강 취소 → 대기자 수강 전환
- 시나리오 3: 결석 → 보강 예약 → 보강 완료
- 시나리오 4: 수납 → 환불 처리
- 시나리오 5: 대시보드 통계 정합성 확인
